Guarded by the marker so it runs exactly once (won't re-grant to new users or undo a deliberate removal). New users get only `App.ChangeLanguage` via `DefaultUser`.

## Fleet crash fixes (from diagnostic bundles)
Investigated crash-recovery bundles from 3 gyms — **three different errors**, not one:

- **classic (18), `DUPLICATE_PHONE:0`** on renewal. Migrated members all share phone `"0"`; renewing one runs the migration-resolve save (`EnsureMigrationDefaultsResolvedAsync`→`UpdateEmployeeAsync`) which threw unhandled. Fix: `EmployeeService.IsBlankPhone()` — blank/`"0"` phones are "unknown", never a duplicate (both Add + Update checks); the migration-resolve save also catches validation errors and shows a friendly message instead of crashing.
- **power (17), `OutOfMemoryException` + 2× `RetryLimitExceededException`.** OOM is the memory-leak class (Basmia mitigations already shipped; handler already GC-special-cases it). The DB retries were showing a scary stack; `DbConnectionHelper.IsConnectionError` now walks the whole inner-exception chain and recognizes EF `RetryLimitExceededException` + connection-pool timeouts → friendly "connection lost" (shared by all 3 apps).
- **ALI (14)** — no managed exception logged (old benign "Application is being shut down" only); recent crash-recovery = unclean/hard exit, same OOM class.

**POS cashier crash (separate, found while testing):** `EmployeeService` ctor has required `IQrPoolService` since 4.6.25, but POS `App.xaml.cs` never registered it → `Unable to resolve service for type 'IQrPoolService'` on cashier startup. Affects any gym with POS enabled on ≥4.6.25. POS now registers it config-driven like WPF.
