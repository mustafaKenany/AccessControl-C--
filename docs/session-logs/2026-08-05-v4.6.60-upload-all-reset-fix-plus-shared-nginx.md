## The bug — basmia's whole gate went dead after a device reset
Operator factory-reset a basmia controller (empty), ran **Bulk Operations → "Upload All"**, and **every** card then read "card not registered" — the gate was dead for all members (subscriptions still valid, card numbers matched → not an expiry/number issue). Root cause in `EmployeeService.UploadAllCardsToDevicesAsync`:
- It **skipped cards it thought were "already synced"** (from the local `CardDeviceSync` table). But a reset device is EMPTY while the DB still marks the cards as on it → it skipped everyone and **pushed nothing** → empty gate.
- It also had **no expiry/frozen filter** (pushed all active *cards* regardless of subscription).

### Fix (both of the operator's requests)
1. **Removed the "already synced" skip** → always re-push every active card (re-push is harmless — `AddAccessCard` overwrites). A reset/swapped controller is now repopulated correctly.
2. **Added the active/non-expired/non-frozen filter** (`ValidTo.Date >= today && !frozen`, via `GetFrozenAsync`) → a 5,000-member gym pushes only active members, not everyone. This matches the already-correct device-row path `SyncAllCardsToDeviceAsync`.

**Immediate workaround given to the operator (no update needed):** use **Devices → "Sync All Players"** on the controller — that path (`SyncAllDataToDeviceAsync` → `SyncAllCardsToDeviceAsync`) already re-pushes all active members with no skip. (The three bulk methods: `SyncAllCardsToDeviceAsync` = per-device, correct; `SyncAllCardsToDevicesAsync` = multi-device, correct; `UploadAllCardsToDevicesAsync` = the Bulk-dialog one that was buggy, now fixed.)

## ⚠️ TWO shared-nginx regressions found & fixed (the "face" project reorganized nginx)
The 2nd project (HikVisionGYM / "face") reworked `/etc/nginx/sites-available/gymapp`. Two gymapp regressions resulted:
1. **`/releases/` no longer proxies to the app.** A new `location /releases/ { alias /var/www/releases/; }` (server `hmtech.solutions`) serves the download dir from disk = **`/var/www/releases/`** (which also holds the face app's `HikVisionGYM-v4.5.x.zip`). But gymapp releases were uploaded to `/var/www/gymapp/wwwroot/releases/` → the 4.6.60 **zip 404'd** even though the API served the manifest. **Fix + NEW DEPLOY RULE:** the gymapp **zip must be copied to `/var/www/releases/`** (shared dir). The **manifest stays** at `/var/www/gymapp/wwwroot/releases/latest.json` (the app's `/api/version/latest` reads it there). Do NOT leave a gymapp `latest.json` in `/var/www/releases/` (the face app might pick it up).
2. **`client_max_body_size` was dropped → nginx default 1 MB → 413-rejecting** all `/api/diagnostics/upload` bundles >1 MB (seen in error.log) AND large `/api/sync` full-syncs (deltas <1MB still passed, which is why the fleet kept syncing). **Fix:** added `/etc/nginx/conf.d/body-size.conf` = `client_max_body_size 210m;` (global http-level, helps both projects; covers the 200MB sync + 25MB diagnostics app caps). `nginx -t` + reload OK. Revert = delete the file.
