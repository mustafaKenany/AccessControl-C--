## 1. BLOCKING BUG — "Incorrect syntax near the keyword 'WITH'" on PO submit

**Symptom**: Submitting a purchase order (supplier + items) threw a SQL error:
*"Incorrect syntax near the keyword 'WITH'. … the previous statement must be terminated with a semicolon."*
Single-row inserts (one product, one supplier) worked; only the multi-row PO insert failed.

**Root cause**: EF Core 8 emits `OPENJSON(@p) WITH (…)` for **multi-row** inserts. `OPENJSON`
requires SQL Server 2016+ at compatibility level 130. On older SQL Server (or a DB left at a
low compat level) the `WITH` clause is rejected. A PO with several line items is the first
multi-row insert most installs hit.

**Fix** (`Infrastructure/DependencyInjection.cs`, `ConfigureSql`): added
`b.UseCompatibilityLevel(120)`. This makes EF generate the classic multi-row insert (no
OPENJSON) that runs on every SQL Server version. Applies to all 3 desktop apps; does **not**
touch the cloud (PostgreSQL/Npgsql).

> Reusable lesson: any "Incorrect syntax near 'WITH'" from EF Core 8 on SQL Server = OPENJSON
> vs. compat level. Fix is `UseCompatibilityLevel(120)`, not a query rewrite.

## 2. Searchable (type-to-filter) dropdowns

Customers may have hundreds/thousands of products — picking from a plain combo is unusable.

- New reusable `SearchableComboBox` style (`Resources/Styles/Inputs.xaml`) — editable dark
  combo with a `PART_EditableTextBox`.
- New attached behavior `Helpers/ComboBoxSearch.cs` — `ComboBoxSearch.SearchPath="Name,NameAr,Barcode"`
  filters the dropdown as you type (case-insensitive, multi-field). Filter clears on
  selection/close; each combo filters only its own bound collection (no cross-contamination).
- Applied to: PO product picker, PO supplier picker, Stock-Movement product filter, and the
  supplier-report picker.
- Plain search boxes (backing-list + filter) added to the **Products**, **Suppliers**, and
  **PO history** lists.

## 3. Weighted-average cost

`InventoryService.CreatePurchaseOrderAsync` previously set `product.CostPrice = last buy price`.
Now it computes a **weighted average**: `(oldStock*oldCost + qty*unitCost) / (oldStock+qty)`,
falling back to the new cost when there's no prior stock/cost. The Sales/profit reports read
this same cost. (Editing a PO intentionally does **not** re-run the averaging.)

## 4. Edit and delete a past purchase order

- **Edit** (`UpdatePurchaseOrderAsync`): the PO history "Edit" button reloads the order into the
  builder (now its own tab). On save, stock is corrected by the **net per-product delta**, the
  PO's stock movements are rebuilt, and the line items are replaced
  (`PurchaseOrderRepository.UpdateWithItemsAsync`, cascade-deletes orphans by EF convention).
- **Delete** (`DeletePurchaseOrderAsync`): reverses stock, removes movements, reverses the
  expense, updates supplier balances, then deletes the PO (items cascade).
- Both **block** if the change would push stock negative (units already sold).

## 5. Cash-Flow stays in sync with PO edits/deletes

Added `Transaction.Reference` (e.g. `"PO-12"`) + a local-only migrator column. The PO's expense
entry is now tagged on create; on edit it's updated to the corrected total (user chose
"auto-adjust to match"); on delete it's reversed. Legacy POs (no tag) get a difference/reversal
entry so totals still reconcile. Transactions are **local-only** (don't sync to cloud).

## 6. Reports

- **New per-supplier report** (`ReportsViewModel` type 6): pick a supplier (searchable) + date
  range → itemized purchases (product/qty/total) + summary (purchased-in-range and all-time
  outstanding balance) + CSV.
- **Print / save-as-PDF for every report**: new `Helpers/TableReportPrinter.cs` (generic A4
  FlowDocument table with gym header) + a "Print / PDF" button. Users pick a printer or
  "Microsoft Print to PDF". Also wired a print button into the **Stock Movements** tab.
- **Dark-themed date filters** (`DarkDatePicker` + `DatePickerTextBox` style in ReportsView) so
  the date pickers match the rest of the app.

## 7. UX restructure + category dropdown

- **Purchase Orders** screen split into 4 real tabs: New Order / History / Movements / Balances
  (was history+builder crammed side-by-side). Edit jumps to the builder tab; save returns to
  history.
- **Admin → Products → Category** is now a **dropdown** (from the `ProductCategory` lookup, the
  same source the POS already used), no longer free text. Existing product categories are folded
  in so no data is lost.

## v4.6.10 — cloud on/off choice at install (offline mode)

**Why**: some sites have no/intermittent internet or don't want the cloud. Forcing cloud on meant
the app logged recurring sync errors that *looked* like a bug but were really "no internet" — a
support time-sink.

**What**: the setup wizard now has a **"Connect to cloud"** checkbox (checked by default). It
writes a new `CloudSyncEnabled` flag to `appsettings.json`.
- `CloudSyncService.IsCloudSyncEnabledFlag()` reads it; **defaults to TRUE when the key is absent**
  so every existing install (Basmia/Noamani/phisphor) is unaffected.
- `IsCloudEnabled()` now returns false when the flag is false → the 5-minute sync timer never
  starts in **either** the main app or the POS (both gate on `IsCloudEnabled()`).
- Also gated on the flag in `App.xaml.cs`: the startup **auto-update check** and the
  **diagnostics upload**. So an offline install makes **zero** cloud calls → no error noise.
- To switch an existing customer offline later: add `"CloudSyncEnabled": false` to their
  `appsettings.json` (no reinstall).

**Trade-off**: offline mode also disables the remote payment-lock (it needs the cloud).

Shipped as **v4.6.10** (ZIP sha256 `7D4F8CE03757F23DD3B85476BD3DB81C31F4C0253E78E0BBD218029BC28B69BA`,
110,607,088 bytes); manifest live, `/api/version/latest` serves 4.6.10.
