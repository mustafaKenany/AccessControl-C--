## The incident — 4.6.53 scheduled-restart regression
Operator reported live gyms "restarting every minute or two" and kicking staff back to the login
screen (basmia's owner hit it at ~23:00). Root cause = the 4.6.53 twice-daily "memory refresh"
restart:
- **Default 16:00 + 23:00** applied to every gym (none set `AppRestartTimes`) — and those are PEAK
  gym hours.
- **`IsSafeToRestart` only checked for an open dialog**, so a gym idling on the dashboard was
  "safe" → restarted → login screen.
- **Worse: it looped.** The "slot done" marker (`_restartSlotsDone`) was in-memory only. The restart
  wiped it, so the relaunched process saw the slot still inside its 30-min window and restarted
  again ~every minute (the DispatcherTimer interval) until the window closed. Two 30-min restart
  loops per day (16:00–16:30, 23:00–23:30).

Confirmed it was NOT the renewal flow (operator first suspected "renew → restart" — coincidence: the
23:00 slot fired right after the renewal dialog closed).

### Fix (App.xaml.cs) — three layers
1. **OFF by default.** `LoadRestartTimes` now defaults to empty; a gym opts in per-machine via
   appsettings `"AppRestartTimes":["05:00"]` (pick an off-hour). Ends the fleet-wide disruption on
   update.
2. **Idle-gated when enabled.** New `IsSafeToRestart(bool requireIdle)`; the scheduled path passes
   `requireIdle:true` → requires no dialog open AND `GetLastInputInfo` user-idle ≥10 min, so it can
   never interrupt active use. OOM self-heal still calls `IsSafeToRestart()` (dialog-only — a failing
   app shouldn't wait for idle).
3. **Persisted slot marker.** On restart we write the slotKey to
   `%LocalAppData%\AccessControlPro\scheduled_restart.txt` BEFORE exiting; the tick skips a slot whose
   key matches the persisted value → the relaunch no longer loops.

**Per-machine hotfix for gyms still on ≤4.6.53** (before they auto-update): set appsettings
`"AppRestartTimes":[]` and relaunch — the next auto-relaunch reads it and the loop stops.

## Also in 4.6.54
1. **Revoke-expired crash fix.** `AccessCardRepository.UpdateAsync` now swallows
   `DbUpdateConcurrencyException` ("expected 1 row, affected 0") — that fires when a concurrent cloud
   sync/migration re-keys a card row (delete+insert) under a detached entity. AccessCard has no
   RowVersion, so it can only mean "row gone" → nothing to persist. Also wrapped the revoke loop's
   per-card bookkeeping in try/catch so one stale card can't abort the batch (the gate revoke already
   succeeded). Reported by basmia after its big first-time sync re-keyed rows.
2. **Daily-pass temp cards auto-free after 24h.** `DailyTempCardStore.LoadOut()` prunes cards issued
   >24h ago (also from disk), so the bracelet number is re-issuable even if staff never click
   "Return". The gate already auto-rejects the card after its issue night; this just clears the local
   "still out" flag.
3. **Daily-pass receipt (ThermalReceipt.BuildHeader).** Phone now prints as a plain LTR string with
   whitespace stripped (RTL was regrouping "07712345678" into "7375 917 0772"). When no logo is set,
   a blank logo area is reserved at the top (operator's choice) — fills automatically once a logo is
   uploaded in Admin → Settings → Browse Logo.
4. **New "Daily Entries" report** (Admin → Reports, tab 7, `SelectedReportType==7`). Per-day list of
   daily-pass income (date/time, tier, amount, detail) with count + total-revenue summary, Print +
   CSV. Identifies daily-pass rows by the same heuristic the Daily Pass dialog uses (category starts
   "Daily" or contains "يومي"). New strings `RptDaily` / `RptDailyRevenue` (EN+AR).
