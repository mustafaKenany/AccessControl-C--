# v4.6.56 + v4.6.57 — zoom/DPI clip fix, pixel-smooth scrolling, Monitor Debug-Assertion fix, Monitor auto-connect

## v4.6.57 — Real-Time Monitor auto-connects before watching
**Shipped 2026-07-08 (same session, right after 4.6.56). LIVE (mandatory) on all 9 gyms.**
Zip SHA-256 `0B53171AA86F3A92BE1495217A9339EC23FDA0771E97FC1721A52190D4FA8DE1`, size `110666464`, `mandatory:true`. Commit: see below.

**Symptom (operator):** clicking **Monitor → بدء (Start)**, then leaving the screen and coming back, threw an error. The operator learned to work around it by running a **manual "connection check"** on a device first, then returning to Monitor — after which it worked.

**Root cause:** `AccessControlSdkWrapper.StartMonitoring` sends `BeginWatch` with `TimeOutMSEL=600` (0.6s). On (re-)entry the controller's TCP session is cold — the previous session's `CloseWatch` tore it down — and 600ms isn't enough to re-establish it, so the first `BeginWatch` errors. The manual "connection check" is `GetDeviceInfo` → `getDevInfo` (a separate native call with a longer timeout) which re-opens the shared native session; the native SDK shares the session across paths, so a subsequent `BeginWatch` then lands on a live connection.

**Fix:** `StartMonitoring` now performs a **connection handshake (`GetDeviceInfo`/`getDevInfo`) per device FIRST**, then the `BeginWatch` loop — so the very first command the device sees is a "connect", exactly what the operator did by hand, now automatic and default. Best-effort (warm-up errors are swallowed; BeginWatch + the 10s keepalive still run). `MonitorViewModel` shows "Establishing device connection..." before the call. Files: `SDK/Wrapper/AccessControlSdkWrapper.cs`, `WPF/ViewModels/MonitorViewModel.cs`. **Not hardware-tested** — verify on a gym after auto-update (Monitor → in/out → leave → return, should work with no manual check).

# v4.6.56 — zoom/DPI clip fix + pixel-smooth scrolling + Monitor Debug-Assertion fix

**Shipped 2026-07-08. LIVE (mandatory) on all 9 gyms.**
Zip SHA-256 `4741B8E35130B53FEA1E86940442A00867795A851401847CEA0475A29EDD81DE`, size `110666244` bytes, manifest `mandatory:true`. Prior live: 4.6.55 (`552d960`).

## Why
Operator (over AnyDesk) reported the **Players (اللاعبون)** screen clipping — the "بدون بطاقة" stat badge was cut off, search box abnormally wide. Root cause turned out to be **Windows display zoom / scaling** enabled on the customer PC (125–150%), which the header layout didn't tolerate. Then, opening the **Real-Time Monitor (المراقبة المباشرة)** popped a blocking **"Microsoft Visual C++ Debug Library — Debug Assertion Failed"** dialog (`atlmfc\afxwin1.inl` line 21 = `AfxGetInstanceHandle`).

## What shipped

### 1. Zoom/DPI-tolerant Players header (`EmployeesView.xaml`)
- **Search + stats row** was a `DockPanel` with the search Border docked Left and no `MaxWidth`. The long placeholder hint (`SearchBoxHint`) *drove the search box width*, pushing the stats StackPanel (and its "بدون بطاقة" badge) off the visual edge — worse under zoom. Rebuilt as a **`Grid` (col0=`*` search, col1=`Auto` stats)**: search clamps `MinWidth=280`/`MaxWidth=620`, stats are `Auto` so they **never clip**; hint TextBlock got `TextTrimming=CharacterEllipsis`.
- **Sync column header overflow:** the dot column was `35px` but its header "مزامنة" is ~48px → overflowed into neighbours. Widened col3 `35→56` in **both** the header grid *and* the row DataTemplate grid (they must stay mirrored), header font `12→11` + trimming.
- **Numeric columns centered** (Fee/Paid/Remaining + Cards) — header + body — for alignment; taller rows (`Padding 18,10 → 18,13`), slightly stronger row separator (`#0D`).

### 2. Pixel-smooth scrolling (all list views)
Added `VirtualizingPanel.ScrollUnit="Pixel"` + `ScrollViewer PanningMode="VerticalOnly"` to the virtualized `ItemsControl` in **EmployeesView, EventsView, LogsView, QrPassView, DeletedRecordsView**. Keeps `IsVirtualizing + Recycling` (the Basmia-OOM guard) while replacing jumpy item-based scroll with smooth pixel scroll. `VerticalScrollBarVisibility` on Employees changed `Visible→Auto` for consistency.

### 3. Monitor Debug-Assertion neutralised (`SDK/Native/CareaIfcNative.cs`)
The **vendor SDK DLLs are debug MFC builds** — `CareaIfc`, `CtrlEx`, `DoorCtrller`, `MyCPlusPlus` all import `MSVCR100D.dll` + `mfc100ud.dll` (confirmed by dumping their import tables; `NativeDlls/` ships the debug runtimes). On the Monitor path an internal MFC `ASSERT` fires and the debug CRT pops a modal Abort/Retry/Ignore dialog that **freezes the whole app**. We can't rebuild the vendor binaries, so `PreloadNativeLibraries()` now calls new **`SuppressNativeDebugAssertions()`**: P/Invokes `_CrtSetReportMode(_CRT_ASSERT/_CRT_ERROR, _CRTDBG_MODE_DEBUG)` into `msvcr100d.dll` (the single shared CRT instance for every vendor DLL, covering ANSI + wide/MFC report paths). This routes reports off the modal window → `_CrtDbgReport` returns 0 = "continue" with no debugger → the assert becomes a no-op, matching release behaviour. Best-effort (try/catch; no-ops if the debug runtime is somehow absent). **Not tested on real controller hardware** — but worst case it does nothing; it only removes a blocking dialog. Native gate binaries untouched (LOAD-BEARING packaging rule preserved).
