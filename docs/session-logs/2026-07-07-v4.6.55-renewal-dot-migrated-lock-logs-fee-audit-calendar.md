## The changes (all operator-driven, from AnyDesk sessions on basmia/Demo)

1. **Renewal green-dot fix (real bug, all gyms).** `RenewSubscriptionAsync` pushed the card to the
   gate and wrote the `CardDeviceSync` table, but never set `AccessCard.IsSyncedToDevice`. The
   Players-list sync dot (`ComputeSyncStatus`) reads *that flag*, so the dot stayed **RED after every
   renewal** even though the card was on the gate. Fix: `card.IsSyncedToDevice = result.Succeeded.Any()`
   in the renew sync loop (persisted by the existing card-save loop). Diagnosed via basmia cloud data:
   the member had exactly 1 active card, so orange was impossible — it was red = flag-not-set.

2. **Migrated members: Edit locked → routed to Renew.** `EmployeesViewModel.EditEmployeeAsync` now
   checks `IsMigratedType(SubscriptionType == "Migrated")`; if migrated, it shows a note and opens
   Renew (correct-inside-Renew, built in 4.6.53) instead of the raw Edit form → no half-corrected
   migrated records. Operator-agreed design; photo-edit for migrated deferred (chose "skip photo").

3. **Logs (السجلات) search.** Enlarged to match the Players box (320px + placeholder) and made it
   **auto-load as you type** — `LogsViewModel.OnSearchTextChanged` now sets `IsDataLoaded=true` and
   debounce-loads (previously search did nothing until "Show All" was clicked). Search already covers
   `Details`/`DetailsAr`/`PerformedBy`/`Action`/`EntityType` (repo `AuditLogRepository`), so with the
   enriched details (below) name/card search works. Events view already had a search box.

4. **Audit enrichment + two-stage gate records.** Register now logs name+card+**dates**. Card-sync
   audit records (`SyncCardToDeviceAsync`/`SyncCardToDevicesAsync`) now include the **player name**
   (loaded via `GetByIdWithCardsAsync`). Renew / freeze / unfreeze / soft-delete each write a **second**
   audit record for the GATE stage ("Player X (card Y) synced/disabled/re-enabled/removed on the
   gate") — so the log clearly shows the DB step and the gate step, both searchable. `LogAuditAsync`
   signature unchanged.

5. **Editable subscription fee (Add-player).** `FeeTextBox` was `IsReadOnly` (auto-filled from plan).
   Now always editable; validation requires `> 0` AND `>= _defaultFee` (the plan price × periods,
   captured in `RecalcFee`) — the operator can charge the plan price or more, never less. New string
   `FeeBelowPlan` ("Fee cannot be less than the plan price ({0})", EN+AR). Renew-dialog fee left
   read-only for now (deferred — offered to extend).

6. **Themed dark calendar.** New `DarkDatePicker` + `DarkCalendar` + `DarkCalendarItem` +
   `DarkCalendarDayButton` + `DarkCalendarButton` styles in `Resources/Styles/Inputs.xaml` (merged
   app-wide) — dark chrome, teal today/selection, 📅 glyph on the field. Applied to AddEmployeeDialog
   `StartDatePicker`/`EndDatePicker` (Start now enabled for custom) and RenewSubscriptionDialog
   `CustomStartDate`/`CustomEndDate`. The Renew custom dates were clipping side-by-side → **stacked
   vertically** with Start/End captions. (Note: `CalendarButton` has no `IsSelected` trigger — use
   `IsFocused`; that was the one build error, fixed.)
