## v4.6.52 (LIVE — commit `444e4ed`, zip SHA `076FE717…667A`, WPF.dll SHA `BEEC5DD2…0430`, mandatory)
Built on the Demo across several rounds, then shipped once the operator confirmed each screen.

1. **Players — live per-filter counts.** Every filter pill now shows a live count (All / Active / Expiring / Renewed / Frozen / Expired) so the owner sees his totals at a glance. `EmployeesViewModel.LoadFilterCountsAsync(search)` reuses the existing `GetPagedAsync`/`GetFilteredPagedAsync` with `size=1` (fast indexed COUNT) and only recomputes when the context changes (page 1), not on page navigation. No new service code.
2. **Responsive Players header.** At 1366×768 the title + 6-button toolbar collided/clipped. Header toolbar and the filter pills are now `WrapPanel`s (reflow instead of clip) + trimmed page margins. It's a resolution-fit issue, not a display setting.
3. **Always-visible scrollbars.** `VerticalScrollBarVisibility="Visible"` on the Players list + both app sidebars (WPF + Admin) so shared-desk staff realize lists scroll. (Offered to sweep every list screen; kept to the high-traffic spots first.)
4. **Devices row cleanup.** The Delete (trash) button was clipping off the fixed 280px Actions column (11 icons). Fix: column 280→330 + `WrapPanel` (nothing clips), then moved the rare actions (device-info, sync-time, change-IP, factory-reset, download-logs, revoke-expired) into a **⋯ More `ContextMenu`** (opened via `DeviceMoreClick` code-behind; menu items bind back with `PlacementTarget.Tag`=VM + `PlacementTarget.DataContext`=device). Kept Connect / Open-Door / Sync-All / Edit / Delete visible.
5. **Daily-pass 80 mm receipt.** `ThermalReceipt.PrintDailyPass(cardNo, from, to, fee)` — gym header + رقم السوار (bracelet no.) + start/end + price, **no member name** (anonymous). Printed straight to the default printer via a Yes/No prompt after issuing a **temp card** (`DailyPassDialog.IssueCardClick`). Requested by harith (Aldoor pool). Gyms have an 80 mm set as default.
6. **Assign-card sync-dot fix.** Repro: assign a card via the Assign-Card dialog (device ticked) → "success" → the gate-sync dot stayed RED. Cause: the VM synced `Cards.LastOrDefault()`, which — if the member had another card record — pushed a stale card and left the newly-assigned one un-synced. Fix: sync the card matching `dialog.CardNumber`. (The whole sync-status mechanism is otherwise correct: `SyncCardToDeviceAsync` sets `IsSyncedToDevice=true` on push success, saves it, and the list reloads → green; red = genuinely not on the gate.)

## Fleet crash-bundle diagnosis (3 gyms, all "crash-recovery")
Pulled the latest crash bundles from the VPS (`/var/www/gymapp/diagnostics/<GymId>/<ts>.zip`, extracted with `python3` zipfile — no `unzip` on the box) and read `logs/crash_log.txt`. **They were NOT the same error:**
- **classic (18):** `InvalidOperationException: DUPLICATE_PHONE:0` in `EmployeeService.UpdateEmployeeAsync ← EnsureMigrationDefaultsResolvedAsync ← RenewSubscriptionAsync` — migrated members sharing phone "0". **A real code bug.**
- **power (17):** `OutOfMemoryException` then 2× `RetryLimitExceededException` (SQL connection pool exhausted) — the memory-leak class (Basmia incident), the DB errors downstream of the OOM.
- **ALI (14):** no managed exception in the recent bundles (only old benign "Application is being shut down" from June 30) — an unclean/hard exit.

All three underlying fixes had already shipped in **4.6.51** (the `IsBlankPhone` DUPLICATE_PHONE fix + the `DbConnectionHelper.IsConnectionError` chain-walking hardening + the OOM special-casing in the global handler). This session confirmed the diagnosis.
