### A2. Gym web dashboards BLANK / nav broken → restored WebSocket headers
The Blazor-**Server** app (`blazor.web.js`, SignalR) needs WebSocket upgrade. The "face" project's nginx
reorg had **stripped the WebSocket + Host headers** from the gymapp `location /` (bare `proxy_pass`) →
SignalR circuit couldn't connect → dashboard loaded but **content blank + every nav click bounced to
/dashboard**, and `/_blazor/negotiate` returned **400**. Fix: restored `proxy_http_version 1.1; Upgrade
$http_upgrade; Connection "upgrade"; Host $host; X-Real-IP; X-Forwarded-*; proxy_read_timeout 100s` on
`location /` + Host/forwarded on `/api/`. Verified negotiate 400→**200**, WebSocket upgrade → **101**.
⚠️ **This was the 3rd face-reorg regression to gymapp — re-verify these headers + the cert whenever the
face agent edits `/etc/nginx/sites-available/gymapp`.**

## D. Releases

### 4.6.62 — Real-Time Monitor "Debug Assertion Failed" popup
Vendor SDK ships DEBUG-MFC binaries; the MFC ASSERT dialog froze the till when the Monitor re-opened.
`CareaIfcNative.SuppressNativeDebugAssertions` (`_CrtSetReportMode`→quiet) was applied ONCE at startup,
but MFC resets the report mode back to the modal dialog on every re-init. Fix: removed the one-time guard
+ re-apply before/after `new ConnectMain()` in `StartMonitoring` and on each 10s keepalive tick. Strictly
safe (idempotent try/catch CRT calls; worst case neutral).

### 4.6.63 — SILENT background updates ⭐
Operators hated the per-launch "update now?" popup (and it re-appeared every launch while an install kept
failing). Now the check **downloads + stages quietly (no prompt)** and installs at the **first safe+idle
moment** (`IsSafeToRestart(requireIdle:true)` = no modal open + 10-min no input, so a sale is never cut
off) → then shows a **"تم تحديث التطبيق من الشركة"** notice on the next launch (`App.SilentBackgroundUpdateAsync`
+ `ApplyStagedUpdateTick`; reuses `DownloadAndStageAsync`/`TriggerInstallAndExit`/`.post_update`). ⚠️ The
silent code is DORMANT until a client sees a version > its own → first real test is the 4.6.64/65 rollout.
**Also: confirmed the shipped `Updater.exe` is the correct 59MB self-contained build** (an earlier "197KB
broken" read was a bad `ls|awk` column parse — same class as the DNS 192.168.1.1 phantom). So a "Updater
launched with the wrong arguments" dialog = someone **double-clicked Updater.exe** (needs ≥2 args from the
app), and an update LOOP = locked files / .NET-not-present, NOT a broken updater.

### 4.6.64 / 4.6.65 — nav + card fix + locked full-screen  ⚠️(re-release)
A nav-only **4.6.64** (`0537bcb`) had already shipped; a 2nd same-numbered 4.6.64 would NOT reach gyms on
it (identical version = no update). So the full set was **re-released as 4.6.65** (`048eb7b`). **LESSON:
never re-ship an already-shipped version number — always bump.** Contents:
1. **Pinned Monitor + Players sidebar** (`MainWindow.xaml`) — owners (esp. new ones) kept losing the
   Monitor (it was the LAST item at the bottom of a 12-item scroll). Now Monitor+Players are a prominent
   accent quick-access pair pinned at the TOP (outside the scroll), removed from the scroll list.
2. **Reverse leading-zero card match** (`AccessCardRepository.GetByCardNumberAsync`) — the reader can DROP

3. **Window locked to full-screen** (`MainWindow.xaml` + `MainWindow.xaml.cs`) — removed the Maximize
