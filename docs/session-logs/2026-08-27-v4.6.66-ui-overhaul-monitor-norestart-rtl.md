## B. ⭐ Monitor no longer restarts the whole app on exit
`MonitorViewModel.StopMonitoringAsync` used to do `Environment.Exit(0)` + relaunch **every time the operator left the Real-Time Monitor** ("لتحديث حالة SDK") — the "program resets" the user complained about (and it also fired on any main-window navigation while monitoring). Root analysis: the SDK is already built for in-process re-entry — `StartMonitoring` calls `StopMonitoring()`+`Initialize()`+a **getDevInfo warm-up handshake**, card ops after monitoring fall back to a fresh subprocess, and the monitor DB lock lets the **same machine re-acquire** always. So the app-restart was legacy overkill. **Fix:** clean stop OFF the UI thread (`Task.Run(_sdk.StopMonitoring())` — CloseWatch sleeps ~2s), then `GC.Collect()`+`WaitForPendingFinalizers()` to release the orphaned native `ConnectMain` (not IDisposable), release the lock, `CloseDisplay()`. No restart, no dialog, no error. ⚠️ **Code-verified by an independent adversarial reviewer, but the FIRST real-hardware test is this 4.6.66 rollout — watch the Monitor on the first gyms; ready to revert if the vendor SDK misbehaves on re-entry.**

## D. ⭐ RTL fix (real bug)
Events / Logs / Deleted Records / Reminders rendered **LTR in Arabic** (title left, filters reversed). Root cause: each view's root had `FlowDirection="{Binding Lang.FlowDirection}"` — a **DataContext-relative binding that fails by timing → the property falls back to its default `LeftToRight`**, overriding the inherited RTL. Proof: Finance/CashFlow have NO such binding, inherit RTL from MainWindow, and were always correct. **Fix:** removed the binding from the 4 views so they inherit direction from MainWindow (correct in both languages). Also: Reminders' raw unstyled `DataGrid` got dark-theme header/cell/row styles; Events/Logs headers restructured (total badge beside the title, one-line filter toolbar).
